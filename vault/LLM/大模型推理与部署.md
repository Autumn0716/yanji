# 大模型推理与部署 · 知识全景

> [!abstract] 主线:一切优化都在和「显存带宽」搏斗
> 训练看算力,**推理看带宽**。Decode 阶段每生成一个 token,FLOPs 极少却要把整个权重 + KV Cache 从 HBM 搬一遍,算术强度 $\sim\!1/d_h$,被死死压在 Roofline 的内存墙一侧。所有推理技术归为三个动作:
> 1. **减少要搬的数据**:GQA/MQA/MLA、KV 量化、权重量化、PagedAttention(去碎片)、KV 驱逐
> 2. **复用已搬的数据**:Prefix Caching / RadixAttention、Continuous Batching(把权重读取摊给更多 token)
> 3. **让搬运被计算掩盖**:FlashAttention(不落盘)、异步 Offloading、Chunked Prefill、CUDA Graph、算子融合

```
请求 ─► Prefill(prompt 并行,GEMM,Compute-bound,决定 TTFT)
        └► Decode(逐 token,GEMV,Memory-bound,决定 TPOT)◄── 99% 优化发生在这
```

# Part I · 第一性原理:FLOPs / 显存 / Roofline

## I.1 参数量与 FLOPs 的「2N / 6N 定律」
设模型参数量 $N$。每个参数在一次前向里参与 **1 乘 + 1 加 = 2 FLOPs**:
- **推理(仅前向)**:每 token $\approx 2N$ FLOPs
- **训练(前向+反向)**:反向是前向 2×,故每 token $\approx 6N$ FLOPs

> [!example] 用 2N 估 Decode 带宽下界
> 70B,fp16,单请求 Decode:算 $2\times70\text{e}9=1.4\times10^{11}$ FLOPs/token,但要读 140GB 权重。A100 带宽 2TB/s ⇒ 读权重 **70ms/token**(≈14 tok/s 上限),而算力只需 $1.4\text{e}11/3.12\text{e}14\approx0.45$ms。**带宽比算力慢 150×** ⇒ 铁的 Memory-bound。这也解释了为何必须 batch:权重读一次摊给 B 个请求,吞吐近似线性涨到算力饱和。

## I.2 推理显存预算(四块)
$$M_\text{total}=\underbrace{N\cdot b_w}_{\text{权重}}+\underbrace{2Lnh_{KV}d_h b_{kv}B}_{\text{KV Cache}}+\underbrace{\text{激活(临时)}}_{\text{小}}+\underbrace{\text{框架/碎片}}_{\sim10\%}$$
- 权重:70B fp16 = 140GB(已超单卡 → 必须 TP 或量化)
- KV:随 $n\cdot B$ 线性涨,长上下文/高并发下**反超权重**成为主项
- 激活:推理不存反向图,只需当前层临时 buffer,通常 < 1GB
- 推论:**短上下文低并发 → 权重主导(weight-only 量化最香);长上下文高并发 → KV 主导(GQA/KV 量化/Offload 最香)**

## I.3 Roofline:一张图判所有瓶颈
$$I=\frac{\text{FLOPs}}{\text{HBM 字节}},\quad I>I^*\!\Rightarrow\text{Compute-bound},\ I<I^*\!\Rightarrow\text{Memory-bound},\ I^*=\frac{\text{算力}}{\text{带宽}}$$

| 硬件 | 带宽 | FP16 算力 | $I^*$ | FP8/INT8 算力 |
|---|---|---|---|---|
| A100-80G | 2.0 TB/s | 312 TFLOPS | ~156 | 624 TOPS |
| H100-80G | 3.35 TB/s | ~990 TFLOPS | ~295 | ~1979 TOPS |
| H200 | 4.8 TB/s | ~990 TFLOPS | ~206 | ~1979 TOPS |

- **Prefill**:$n$ 个 token 共享一次权重读取,$I\sim n$,轻松越过 $I^*$ → 吃满 Tensor Core。
- **Decode(batch B)**:$I\sim B$。要让 Decode 也 Compute-bound,需 $B\gtrsim I^*\approx 150$+,但 KV 显存常先爆 → 现实里 Decode 多半卡在带宽。
- **量化的双重收益**:权重 fp16→int8 不仅显存减半,**HBM 字节减半直接令 $I$ 翻倍**,把 Decode 往算力侧推。

# Part II · 注意力机制与位置编码

## II.1 注意力复杂度账本(逐项)
单层、序列 $n$、hidden $d$:
| 子模块 | FLOPs | 量级 | 备注 |
|---|---|---|---|
| QKV 投影 | $6nd^2$ | $O(nd^2)$ | 权重侧 |
| $S=QK^\top$ | $2n^2d$ | **$O(n^2d)$** | 空间 $O(n^2)$ |
| softmax | $O(n^2)$ | — | 行内归一 |
| $O=PV$ | $2n^2d$ | $O(n^2d)$ | |
| 输出投影 + FFN(4×) | $\sim16nd^2$ | $O(nd^2)$ | FFN 占权重大头 |

> [!warning] 四诱饵辨析(必考)
> $O(nd)$=单头某步 · $O(nd^2)$=线性层/FFN · **$O(n^2d)$=注意力核心** ✅ · $O(n^2d^2)$=乱叠二次。
> 交叉点:$n^2d$ vs $nd^2$ ⇒ $n=d$。**短序列 FFN 主导(权重读取瓶颈),长序列注意力主导(KV/算力瓶颈)**。

## II.2 MHA / GQA / MQA / MLA

| 方案 | $h_{KV}$ | 单步 KV 读取 | 质量 | 代表 |
|---|---|---|---|---|
| MHA | $h$ | $2Lhd_h{\cdot}2$ | 基线 | GPT-3 |
| GQA | $1{<}h_{KV}{<}h$ | $2Lh_{KV}d_h{\cdot}2$ | 折中 | Llama2/3-70B(G=8) |
| MQA | $1$ | $2Ld_h{\cdot}2$ | 略降 | PaLM/Falcon |

- 关系 **MHA>GQA>MQA**;每 KV 头被 $h/h_{KV}$ 个 Q 头共享;$h_{KV}{=}1$→MQA,$=h$→MHA,GQA 是连续插值。
- MHA→GQA 可"uptraining"(KV 头均值池化 + 少量步微调),近无损。

> [!info] MLA(Multi-head Latent Attention,DeepSeek)
> KV **低秩压缩**为单个 latent $c_t=W_{DKV}h_t$ 存进 Cache,用时上投影还原 $K=W_{UK}c,V=W_{UV}c$;RoPE 维度**解耦**(单独一路携带位置,不参与压缩,避免压缩破坏旋转不变性)。KV Cache 比 GQA 还小一个量级,质量近 MHA。"减字节"路线里继量化后的结构级突破。

## II.3 替代注意力(降低 $n^2$ / 去 KV)
- **Sliding Window Attention(Mistral)**:每 token 只看最近 $W$ 个,KV Cache 封顶 $W$(不随 $n$ 涨);感受野随层数线性扩张($L$ 层 → $L\times W$)。
- **Sparse / Dilated Attention**:固定/跨步稀疏模式,$O(n\sqrt n)$ 或 $O(n\log n)$。
- **Linear Attention(RWKV 等)**:核特征映射 $\phi$ 把 $\text{softmax}(QK^\top)V$ 改写成 $\phi(Q)(\phi(K)^\top V)$,结合律使复杂度 $O(nd^2)$、且有**递归形式 → 常数状态、无增长 KV**。代价:表达力/检索能力弱于 softmax 注意力。
- **SSM / Mamba**:状态空间递归 $h_t=\bar A h_{t-1}+\bar B x_t,\ y_t=Ch_t$,**选择性扫描**让参数随输入变化;推理 **O(1)/token 显存(定长状态)、O(n) 总算**,无 KV 爆炸;训练用并行扫描。是 Transformer 的强力挑战者,长序列尤优。

## II.4 RoPE 与长度外推
**复数视角**:把 $(x_{2i},x_{2i+1})$ 看作复数 $z_i$,RoPE 即乘 $e^{im\theta_i}$;内积 $\langle R_mq,R_nk\rangle=\text{Re}\sum_i q_i\bar k_i e^{i(m-n)\theta_i}$,**只依赖 $m-n$**(旋转群:$R_m^\top R_n=R_{n-m}$)。零额外算力,仅作用 $Q,K$ 不动 $V$,不改 $O(n^2d)$。
**外推($s=L_\text{new}/L_\text{train}$)**:
- **PI 位置插值**:全频压 $\theta_i/s$,简单但糊高频。
- **NTK-aware**:改基底,**高频(小 i)几乎不缩、低频(大 i)按 s 缩** → 频率空间插值,保高频分辨率。
- **YaRN**:分频段 + attention 温度修正,长上下文工程主流。
- **StreamingLLM(attention sink)**:发现前几个 token 吸走大量注意力(softmax 必须找地方放权重)→ 保留 4 个 sink token + 滑窗 KV,即可**无限流式**不崩,无需微调。

# Part III · KV Cache 全谱

## III.1 加速原理(O(n²d)→O(nd),解答题)
生成第 $n{+}1$ token:无缓存重算前 $n{+}1$ 位置 $K,V$ → 单步 $O(n^2d)$;有缓存只算当前 $q$,$s=qK^\top,o=\text{softmax}(s)V$ → 单步 $O(nd)$。**二次项→一次项,降 $n$ 倍**,空间换时间。

## III.2 显存公式 ⭐
$$\boxed{M_{KV}=2\,L\,n\,h_{KV}\,d_h\,b_{kv}\,B}$$
| 例 | 参数 | 结果 |
|---|---|---|
| 卷子题 | $L{=}32,h{=}32,d_h{=}128,n{=}4096$,fp16 | $2^{36}\text{B}=64$GB |
| 70B 单 token | $L{=}80,h{=}64,d_h{=}128$,fp16 | ≈2.6 MB → 128k≈332GB |

## III.3 PagedAttention
**病**:按 max_len 预分配连续块 → 内部碎片(实际<预分)+ 外部碎片(长短留空)+ 预分配浪费,利用率 20–40%。
**药**:仿 OS 分页,KV 切固定 **Block(16 token)**,**Block Table** 逻辑→物理映射,按需分配,利用率 >90%,支持 **CoW**(beam/并行采样共享前缀块)。
**边界**:管显存布局,**不**管算子融合(诱饵)。

## III.4 长上下文 KV 压缩 / 驱逐(超纲高频)
当 $n$ 大到 KV 装不下,几条正交路线:
| 方法 | 思想 | 关键 |
|---|---|---|
| **KV 量化** | fp16→int8/fp4 | 直接砍带宽,Decode 收益最直接 |
| **H2O** | 保留"重击者"(累计注意力高)+ 近期 token | 驱逐低贡献 KV |
| **SnapKV** | prompt 阶段聚类选重要 KV | 压缩 prompt KV |
| **StreamingLLM** | sink + 滑窗 | 定长 KV 无限流 |
| **滑窗注意力** | 结构上封顶 KV=W | Mistral |
| **MLA / 跨层共享(YOCO)** | 低秩 / 层间复用 KV | 结构级 |
| **Offloading** | KV 下沉 CPU/SSD | 见 Part VIII |

## III.5 Prefix Caching / RadixAttention
相同前缀(System Prompt、few-shot、多轮历史)的 KV 只算一次、跨请求复用。SGLang 用 **radix tree(前缀树)** 自动匹配最长公共前缀,命中即跳过 Prefill。对"大量请求共享长系统提示"的场景吞吐数倍提升,也直接救显存(见压轴 90GB 节省)。

# Part IV · 调度与批处理

## IV.1 三种 Batching

| 策略 | 机制 | 定位 |
|---|---|---|
| Static | 凑满批跑完再换 | 长短互等,GPU 闲 |
| **Continuous** | iteration/token 级调度,完成即让位 | vLLM 核心,又名 Iteration-level |
| In-flight | TRT-LLM 实现名 | =Continuous + 多模/多请求,非完全等价 |

## IV.2 Continuous Batching 内部机制
- **双队列**:waiting(待 Prefill)/ running(Decode 中);每个 iteration 调度器决定谁进 running。
- **抢占(preemption)**:GPU KV 满时踢出低优先级请求,二选一:
  - **Swap**:KV 搬到 CPU 内存,恢复时搬回(省重算,费 PCIe)
  - **Recompute**:丢弃 KV,稍后重跑 Prefill(省内存带宽,费算力)
- **调度目标**:在 SLO(TTFT/TPOT)约束下最大化 **goodput**;优先保 running 的 KV 命中。

## IV.3 Chunked Prefill(解答题)⭐
**病**:32k 长 Prefill 单批数十 ms,阻塞在线 Decode → P99 毛刺(长 Compute-bound 压短 Memory-bound)。
**药**:Prefill 切 512–2048 token chunk,每 iter 跑一个,与 Decode **同 batch 混跑**。
- chunk 大小:单 chunk 时间 ≤ Decode 步间隔(~10–20ms)。
- 红利:Compute-bound 的 Prefill chunk + Memory-bound 的 Decode **算密互补**,一起填满 SM(见压轴 b)。

## IV.4 Prefill/Decode 分离(Disaggregation)
TTFT 由 Prefill 决定、TPOT 由 Decode 决定,两者对资源诉求相反(Prefill 吃算力、Decode 吃带宽)。**P/D 分离**把两类实例物理拆开:
- Prefill 集群算完 KV,经 **NVLink/RDMA** 传给 Decode 集群继续生成。
- 各自独立扩缩容、独立 batch 策略,互不干扰毛刺。
- 代表:DistServe(理论)、**Mooncake**(以 KV Cache 为中心的池化架构)。代价:KV 跨机传输带宽与延迟。

# Part V · 量化与压缩

## V.1 三大 PTQ 思想 ⭐

| 算法 | 核心 | 谱系 / 一句话 |
|---|---|---|
| **GPTQ** | Hessian 二阶,逐列量化 + 误差补偿 | OBS/OBQ 血统;边量边修 |
| **AWQ** | Activation-aware,缩放保护显著权重通道 | 1% 通道定生死 |
| **SmoothQuant** | 等价变换迁移激活离群点到权重 | 难量化的激活→易量化 |

皆 **PTQ**(免训练);对立 **QAT**(训练中模拟量化,精度高成本大)。

## V.2 算法内核(加深)
- **GPTQ**:基于 OBS(Optimal Brain Surgeon),量化某权重后用 Hessian 逆 $H^{-1}$ 把误差补偿到**尚未量化**的权重上,逐列推进;Hessian 用校准集激活近似 $H\approx 2XX^\top$。
- **AWQ**:观察"按激活幅度选的 1% 显著权重通道"决定精度;对这些通道乘缩放 $s$(等效搬到激活的逆缩放),搜索最优 $s$ 最小化量化误差;**weight-only,不量化激活**,适配 W4A16。
- **SmoothQuant**(解答题):
$$XW=(XS)(S^{-1}W)=\hat X\hat W,\quad s_j=\frac{c_j^\alpha}{w_j^{1-\alpha}},\ \alpha\in[0,1]$$
$\alpha{=}0$ 只缩权重;$\alpha{=}1$ 离群全迁权重使激活平坦;$\alpha\approx0.5$ 平衡 → 双侧 INT8 = **W8A8**。

## V.3 为何激活比权重难量化(根因)
激活在**少数通道**(0.1–1%)有 Outlier(30×+),per-tensor scale 被撑大、正常通道有效比特骤减、误差被离群通道主导;权重分布平滑无此问题。⇒ 解法都围绕"隔离/迁移离群通道"。

## V.4 精度格式与粒度
- **粒度**:per-tensor ⊂ per-channel ⊂ **per-group(128)**,越细越准越慢。
- **格式**:INT8 / INT4(GPTQ/AWQ)/ **FP8 E4M3(H100 原生)** / E5M2 / NF4(QLoRA)/ MXFP4(块缩放微缩浮点)。
- **数值类型对比**:

| 类型 | 字节 | 指数/尾数 | 特点 |
|---|---|---|---|
| FP32 | 4 | 8/23 | 基准 |
| FP16 | 2 | 5/10 | 范围窄(±65504,易溢出) |
| **BF16** | 2 | 8/7 | 范围同 FP32、尾数少 → 训练首选 |
| FP8 E4M3 | 1 | 4/3 | 推理/前向 |
| FP8 E5M2 | 1 | 5/2 | 梯度/范围优先 |

> softmax / LayerNorm / 残差累加通常**保 fp32** 防数值崩。
- **W4A16 vs W8A8**:前者省显存(Decode 友好),后者省算力(Prefill 友好)。**KV Cache 量化**(KV→int8/fp8)单独砍 Decode 带宽,性价比极高。

## V.5 量化之外的压缩
- **剪枝(Pruning)**:非结构化(magnitude,难加速)vs 结构化(剪头/层/通道,真加速);**2:4 半结构化稀疏**(每 4 权重留 2,NVIDIA Sparse Tensor Core 2×)→ SparseGPT / Wanda。
- **蒸馏(Distillation)**:teacher→student,匹配 logits/特征/响应;DeepSeek-R1 蒸馏小模型即此路。
- **低秩分解**:权重 $W\approx UV$ 降参;LoRA 是其训练侧亲戚。

# Part VI · 解码加速与采样

## VI.1 Speculative Decoding(无损)⭐
小草稿 $q_\theta$ 一次猜 $k$ 个,大目标 $p_\phi$ **一次前向并行验完**(把逐 token 的 Memory-bound 变成批量 Compute-bound)。
**接受/拒绝 + 严格服从 $p$**:
$$r_i=\min\!\Big(1,\frac{p(\tilde x_i)}{q(\tilde x_i)}\Big),\quad \text{拒绝重采样}\ p_\text{resample}(x)=\frac{(p(x)-q(x))^+}{\sum_{x'}(p(x')-q(x'))^+}$$
$$P(\text{out}{=}x)=q\min(1,\tfrac pq)+\Big[\textstyle\sum(q-p)^+\Big]\frac{(p-q)^+}{Z}=\min(q,p)+(p-q)^+=p(x)$$
⇒ 输出精确等于 $p$,**Greedy/Top-p 都无损**。
**加速比**:$S(k)=\dfrac{\alpha(1-\alpha^k)}{1-\alpha}\cdot\dfrac{t_v}{t_d+t_v}$;期望接受(独立近似)$\approx\sum_{i=1}^k\alpha^i$;$k{=}4$ 稳得 2 个需 $\alpha\gtrsim0.54$。
**免草稿**:Medusa(多预测头)、**EAGLE-2/3**(特征层自回归,SOTA)、Lookahead(n-gram 雅可比)。**树注意力**:一次验证多条候选分支(树形 mask),提升每轮接受数。

## VI.2 采样数学(逐个说清)
按 vLLM 典型顺序 **温度 → top-k → top-p → min-p**:
| 旋钮 | 公式/规则 | 直觉 |
|---|---|---|
| **Temperature** | $\text{softmax}(z/T)$ | T→0 贪心、T→∞ 均匀;T↑更发散 |
| **Top-k** | 留概率最高 $k$ 个,重归一 | 硬截断尾部 |
| **Top-p(Nucleus)** | $V_p=\min\{k\mid\sum_{i=1}^k p_i\ge p\}$ | 自适应集合大小 |
| **Min-p** | 留 $p_i\ge p_\text{min}\cdot\max_j p_j$ | 按峰值自适应,低熵时更紧 |
| **Repetition penalty** | seen token 的 $z$ 除以 $\rho{>}1$ | 抑制复读 |
| **Typical** | 选局部熵附近 token | 抑制过于离谱/过于平庸 |

## VI.3 约束 / 结构化解码(Guided Decoding)
要求输出严格 JSON/正则/语法:把 schema 编译成 **FSM/下推自动机**,每步只允许"合法后继 token",对非法 token 的 logits 置 $-\infty$(掩码)。
- **Outlines**:正则→FSM,预编译转移表,每步 O(1) 取掩码。
- **xgrammar / llguidance**:上下文无关文法(CFG),处理嵌套结构,kernel 级加速。
- **Token healing**:修复 tokenizer 边界(避免把 `"` 和后续字符错切)。
- 代价:掩码构建 + 词表级 gather;与采样在 logits 层叠加。

# Part VII · 核函数与并行

## VII.1 FlashAttention
**标准 HBM 账**:读 $Q,K$ $2nd$ + 写 $S$ $n^2$ + 读 $S$ 写 $P$ $2n^2$ + 读 $P,V$ 写 $O$ $n^2{+}2nd$ → $O(n^2{+}nd)$,$n^2$ 中间矩阵反复读写是元凶。
**Tiling + Online Softmax**(SRAM $M$,块 $\Theta(M/d)$;$Q$ 行块、$K,V$ 列块):
$$m^\text{new}=\max(m^\text{old},\text{rowmax}\,S_{ij}),\quad \ell^\text{new}=e^{m^\text{old}-m^\text{new}}\ell^\text{old}+\text{rowsum}\,e^{S_{ij}-m^\text{new}}$$
$$\tilde O^\text{new}=e^{m^\text{old}-m^\text{new}}\tilde O^\text{old}+e^{S_{ij}-m^\text{new}}V_j,\qquad O_i=\tilde O_i/\ell_i$$
rescale 因子保证分块累加 = 全局 softmax(减 max 防溢出),$S,P$ **从不写回 HBM**。
**Recomputation**:反向不存 $S,P$,重算 $S_{ij}$ → 多 $O(n^2d)$ FLOP,但 HBM 仍 **$O(N^2d^2/M)$**;"以算代存"。
**谱系**:FA-2(并行/warp 调度)→ FA-3(Hopper 异步 + FP8)→ **FlashDecoding**(Decode 时 q 仅 1 行,沿 KV 序列维并行,救长上下文)。

## VII.2 算子融合 + CUDA Graph
- **融合(Fusion)**:把多个小 kernel 合一,省 kernel launch + 省 HBM 往返。常见:QKV 三投影合一 GEMM、RMSNorm+残差、Rotary+Attention、SwiGLU($\text{SiLU}(xW_1)\odot(xW_2)$)、bias+激活。
- **CUDA Graph**:Decode 每步是一串极小 kernel,launch 开销(μs 级)能占大头;把整串 kernel **录制一次、重放一次 launch**,消除 CPU 提交瓶颈。对小 batch Decode 提速显著。

## VII.3 并行策略

| | 切什么 | 推理要点 |
|---|---|---|
| **TP** | Attention/MLP **权重**(列切+行切配对) | 每层 1 次 AllReduce;**RMSNorm/LayerNorm 被复制不切**;Embedding/LM Head 按词表切;受 NVLink 约束,通常≤8 卡 |
| **PP** | 按 **layer/stage** | 瓶颈 Bubble + 跨 stage 通信;需 micro-batch 填流水 |
| **SP** | LayerNorm/Dropout 等**沿序列激活** | 降长序列激活显存,常与 TP 叠 |
| **EP** | MoE **专家**分卡 | all-to-all 路由 token |
| **DP** | 整模型复制 | 服务横向扩容 |
| **CP** | 超长上下文沿序列(Ring Attention) | KV 分布式 |

> [!warning] 经典错项:"TP 所有层都切、无复制层" —— 错,RMSNorm 每 rank 复制。

## VII.4 通信原语(并行的隐藏成本)
- **AllReduce = ReduceScatter + AllGather**;TP 在 Attention/MLP 后各一次 AllReduce。
- **Ring AllReduce**:带宽最优,传输量 $2\frac{N-1}{N}\times$ 数据,与卡数近似无关。
- **小消息延迟受限 / 大消息带宽受限**;Decode 的 TP 通信常是小消息 → 延迟敏感,NVLink(600GB/s,低延迟)远优于 PCIe。
- all-to-all(EP)是 MoE 的主要通信瓶颈。

# Part VIII · 系统级综合与服务化

## VIII.1 压轴:单 A100-80G 跑 70B,在线对话 + 128k 摘要

| 现象 | 病根 | 药方 |
|---|---|---|
| (a) 长 Prefill 致 Decode P99 毛刺 | 长 Compute-bound 阻塞短 Memory-bound | **Chunked Prefill** |
| (b) 并发上去 SM 仅 45% | Decode 是 GEMV 算密低 + padding | 加并发(GEMV→GEMM)、GQA 减 KV、Chunked 混跑、CUDA Graph/融合、Prefix Caching |
| (c) 128k 频繁 OOM | 单任务 KV 332GB≫80GB | **PagedAttention + KV Offloading + Prefix Caching** 三级存储 |

**三级存储数据流 + 量化收益**(单 token KV≈2.6MB):
```
GPU 显存(近 4k,~10GB) 热 ─┐ PCIe 异步 prefetch/evict(FlexGen)
CPU 内存(中段 100k,~260GB) 温 ─┤ 瓶颈:PCIe 64GB/s
NVMe SSD(远 24k,~60GB) 冷 ─┘ 解法:lookahead 预取 + CUDA stream 掩盖
Prefix Caching:System Prompt 跨 10 并发复用,省 ~90GB
⇒ 单卡 128k 并发 0→5~10,吞吐 5×+
```
**SM 为何能提**(因果):并发↑摊薄权重读取、GEMV 凑 GEMM;GQA 降 KV 抬算密;Chunked 算密互补;融合减空泡;Prefix Caching 抬有效 batch。

## VIII.2 Multi-LoRA 服务(一基座多适配器)
单 base + 大量 LoRA adapter 同时在线:
- **S-LoRA**:adapter 权重统一分页(Unified Paging),按请求批量 gather;base 只存一份。
- **Punica**:自定义 **SGMV** kernel,一个 batch 内不同请求用不同 adapter 也能高效批算。
- 价值:把"每 adapter 一个部署"变成"一卡服千 adapter",显存/利用率巨省。

## VIII.3 框架 · 指标 · 经济学
**框架**:vLLM(PagedAttn,标准)· TRT-LLM(极致 kernel + In-flight)· SGLang(RadixAttention)· LMDeploy(TurboMind)· llama.cpp(GGUF 边端)。
**SLO 指标**:TTFT(Prefill 决定)· TPOT/ITL(Decode 决定)· Throughput(tok/s)· **Goodput**(满足 SLO 的有效吞吐)。
**延迟-吞吐权衡**:batch↑ → 吞吐升到算力饱和、但单请求延迟升 → 存在 **Pareto 前沿**;生产按 SLO 选工作点。$/token 反比于吞吐 × 利用率,故"提 SM 占用"直接等于"降成本"。

## IX.1 公式速查

| 量 | 公式 |
|---|---|
| 推理/训练 FLOPs | $2N$ / $6N$ per token |
| 注意力时间/空间 | $O(n^2d)$ / $O(n^2)$ |
| KV Cache 显存 | $2Lnh_{KV}d_h b_{kv}B$ |
| 算术强度 | FLOPs/HBM 字节;$<I^*{=}$算力/带宽 ⇒ Memory-bound |
| Roofline 拐点 | A100≈156、H100≈295 FLOP/B |
| 接受概率 | $\min(1,p/q)$;拒绝 $(p-q)^+/Z$ |
| Spec 加速比 | $\frac{\alpha(1-\alpha^k)}{1-\alpha}\cdot\frac{t_v}{t_d+t_v}$ |
| Online softmax | $m,\ell,\tilde O$ 三式 rescale |
| FA IO | $O(N^2d^2/M)$ |
| SmoothQuant | $(XS)(S^{-1}W),\ s_j=c_j^\alpha/w_j^{1-\alpha}$ |
| AllReduce 传输 | $2\frac{N-1}{N}\times$ 数据(Ring) |

## IX.2 一句话记忆锚

- 训练吃算力,**推理吃带宽**;Decode 是主战场。
- KV Cache:**空间换时间**,$O(n^2d)\to O(nd)$;但显存随 $nB$ 爆。
- GQA/MQA/MLA = 减 KV 头/字节;PagedAttn = 去碎片;Prefix Cache = 去重复;Offload = 装不下。
- Prefill=Compute-bound,Decode=Memory-bound;**加 batch / 量化 = 抬算术强度**。
- 量化:GPTQ-Hessian / AWQ-显著通道 / SmoothQuant-迁移;激活难因**少数通道离群**。
- Spec Decoding 拒绝采样 → **严格无损**;FlashAttn online softmax + 以算代存 → IO $O(N^2d^2/M)$。
- TP 切权重(RMSNorm 复制)、PP 切层(Bubble)、SP 切序列激活、EP 切专家(all-to-all)。
