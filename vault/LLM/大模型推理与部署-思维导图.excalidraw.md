大模型推理与部署
核心主线:推理 = 和「显存带宽」搏斗 ^t1

Prefill(预填充)
• prompt 并行 · GEMM
• Compute-bound
• 决定 TTFT(首 token) ^t2

Decode(解码) ★主战场
• 逐 token · GEMV
• Memory-bound(带宽墙)
• 决定 TPOT(token 间隔) ^t3

三类动作 = 所有推理优化的归宿 ^t4

① 减少要搬的数据
──────────
• GQA / MQA / MLA(减KV头·低秩)
• KV 量化(int8 / fp8)
• 权重量化:GPTQ·AWQ·SmoothQuant
• PagedAttention(去碎片)
• KV 驱逐:H2O·StreamingLLM·SnapKV ^t5

② 复用已搬的数据
──────────
• Prefix Caching / RadixAttention
  (共享 System Prompt 的 KV)
• Continuous Batching
  (权重读取摊给更多 token)
• 增大 batch → 抬算术强度
  (把 Decode 推向 Compute-bound) ^t6

③ 让搬运被计算掩盖
──────────
• FlashAttention(tiling·不落盘·以算代存)
• Chunked Prefill(治 P99 毛刺)
• KV Offloading(GPU→CPU→SSD)
• CUDA Graph + 算子融合
• Speculative Decoding(无损·并行验证) ^t7

并行:TP 切权重(RMSNorm 复制)· PP 切层(Bubble)· SP 切序列 · EP 切专家
判据:算术强度 I = FLOPs / HBM 字节 ;I < I*(A100≈156)⇒ Memory-bound ^t8
