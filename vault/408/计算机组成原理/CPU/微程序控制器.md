# 微程序控制器

> [!abstract] 一句话
> 每条机器指令对应一段**微程序**（微指令序列），存在控制存储器 **CM** 里；用读 CM 代替复杂组合逻辑发控制信号。

## 基本结构

| 部件 | 作用 |
| --- | --- |
| **CM**（控制存储器） | 存放各指令微程序，常用 ROM |
| **CMAR** / μPC | 微地址寄存器，指向下一条微指令 |
| 地址译码器 | 译 CM 地址 |
| **CMDR** / μIR | 微指令寄存器，暂存读出的微指令 |
| **微地址形成部件** | 顺序 / 分支 / 映射出下一条微地址 |

## 条数关系（常考）

- 指令系统有 **n** 条机器指令 → 至少 **n 个执行用微程序** + **1 个取指微程序**
- 或者说：**微程序段至少 n+1**
- 取指与执行看起来是两段，逻辑上同属「解释一条机器指令」的整体

## 编码方式

### 直接编码

![直接编码](/vault/408/%E8%AE%A1%E7%BB%84/CPU/%E9%99%84%E4%BB%B6/Screenshot%202026-07-10%20at%2021-12-10.png)

- 微命令与微指令位几乎一一对应；码点长、并行性好、硬件简单

### 字段直接编码

![字段直接编码](/vault/408/%E8%AE%A1%E7%BB%84/CPU/%E9%99%84%E4%BB%B6/Screenshot%202026-07-10%20at%2021-12-18.png)

- 互斥微命令放同一字段编码；缩短字长

### 字段间接编码

- 某字段的含义依赖另一字段（更压缩，译码更复杂）

## 统计口径

> 指令的**平均微操作数**统计通常**不包含**取指、间指、中断等辅助段（看清题目定义）。
