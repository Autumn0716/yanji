# 输入输出系统

> [!abstract] 一句话
> I/O 解决「慢设备 ↔ 快主机」：接口做缓冲与控制；传送方式按 CPU 介入程度从程序查询 → 中断 → DMA → 通道递增「解放 CPU」。

```mermaid
flowchart LR
  CPU[CPU] --> IF[I/O 接口]
  IF --> DEV[外设]
  DMA[DMA/通道] -.-> MEM[主存]
  DEV -.-> DMA
```

与总线的关系见 [总线](../总线/总线.md)（I/O 总线、DMA 总线、通道程序在主存）。

---

## 1. I/O 接口（I/O 控制器）

介于主机与外设之间，典型组成：

| 部件 | 作用 |
| --- | --- |
| 数据缓冲寄存器 | 速度匹配、暂存一拍数据 |
| 状态/控制寄存器 | 忙/就绪/错、启停、方式位 |
| 地址译码 | 选中本接口的端口 |
| 时序与控制逻辑 | 产生设备读写、中断/DMA 请求等 |
| 中断/DMA 相关电路 | 请求、排队、应答 |

### 内部接口 vs 外部接口（并/串行）

I/O 接口夹在主机与外设之间，两侧各有一套接线：

```mermaid
flowchart LR
  CPU[CPU/主存] -- 系统总线 --> INT[内部接口]
  INT --- BUF[缓冲与控制]
  BUF --- EXT[外部接口]
  EXT -- 电缆 --> DEV[外设]
```

| 侧 | 连谁 | 并/串？ | 原因 |
| --- | --- | --- | --- |
| **内部接口** | 系统总线（CPU/主存） | **并行**（教材口径：与主机之间总是并行） | 系统数据总线是多位宽的，按字节/字/多字一次传送；接口对主机侧必须跟总线对齐 |
| **外部接口** | 外设（经电缆） | **可并行也可串行** | 取决于外设与线缆：近距、位多可用并行；远距、少线、标准串口/USB 等用串行 |

> [!IMPORTANT]
> **内部接口怎么「串行」？——按 408/教材考点：不这么考。** 主机侧走系统总线，数据通路是并行的；所谓串行发生在**外设侧**。若外设串行，接口内部做串↔并，**对内仍并行交总线**。
>
> 「并行接口 / 串行接口」这对分类名，通常只描述**外部接口**怎么连外设。

**一般情况（答题模板）：**

- 内部：并行
- 外部：可并可串（串行时接口内有串并转换）

例：UART = 内并行 + 外串行；老式并口打印机 = 外设侧也并行。

### 统一编址 vs 独立编址

| | 统一编址（存储器映像 I/O）RISC常用 | 独立编址（I/O 映像）INTEL常用 |
| --- | --- | --- |
| 端口地址 | 占用主存地址空间一段 | 单独 I/O 地址空间 |
| 指令 | 用访存指令（如 `MOV`）访问端口 | 专用 `IN`/`OUT`（或同类） |
| 优点 | 指令集简单、可对端口用多种寻址 | 不占主存空间，译码可更简单 |
| 缺点 | 占地址；外设与主存译码需区分 | 要增加 I/O 指令与控制线 |

## 2. 四种 I/O 控制方式（核心对照）

| 方式 | CPU 介入 | 数据通路直觉 | 适用 |
| --- | --- | --- | --- |
| **程序查询（轮询）** | 一直查状态 | CPU ↔ 接口 ↔ 设备 | 简单、低速；CPU 浪费大 |
| **程序中断** | 仅在设备就绪时打断 | 同上，但异步通知 | 中低速；每字/每字符常打断一次 |
| **DMA** | 成批传送时几乎不管 | **设备 ↔ 主存**（经 DMA），CPU 只始末 | 高速成批（磁盘等） |
| **通道** | 更少；通道执行通道程序 | 通道管多设备/多路 | 大型机、多设备并行 |

> [!TIP]
> 记忆梯度：**查询最耗 CPU → 中断按次打断 → DMA 成块搬 → 通道像「小 I/O 处理器」**。

## 3. 程序查询方式

1. CPU 启动设备  
2. 循环读状态寄存器，直到「就绪」  
3. 传送一个数据  
4. 若未完，回到 2  

- **优点**：硬件简单  
- **缺点**：CPU 空转；难重叠计算与 I/O

## 4. 中断方式

### 基本过程（常考顺序）

1. 设备就绪 → 发**中断请求**  
2. CPU 在指令周期末（或规定点）响应（开中断、优先级允许）  
3. **关中断**、保护断点与程序状态（谁保什么见下表）  
4. 形成/取得**中断向量** → 进中断服务程序  
5. 开中断（若允许嵌套）→ 服务（常传一个数据或处理事件）  
6. 恢复现场、**开中断**、返回断点（恢复现场可由软件实现）

### 谁保存什么（外部中断·高频）

| 内容 | 谁保存 / 谁完成 |
| --- | --- |
| **PC、PSW**（断点与程序状态字） | **中断隐指令**（硬件自动，不占程序指令） |
| **CPU 模式 → 内核态** | **硬件**（随隐指令改 PSW/态位；软件不能自行提权） |
| **通用寄存器**等其余现场 | **操作系统**（中断服务程序入口处由软件保存） |

> [!TIP]
> 记法：**硬件保「回得去」并切入内核态（PC/PSW/模式），软件保「算得完」（通用寄存器）**。模式细节见 [操作系统概述·CPU 运行模式](../../操作系统/概述.md)。

### 中断向量表

- **结构**：以**数组**存放各中断服务程序的**入口地址**（或向量）
- **目的**：CPU 用中断号作下标 **O(1)** 取入口，尽快跳到对应处理代码，**保障中断响应的瞬时性**
- **对照**：向量中断靠表（或硬件给出的向量）直接定位；非向量则要软件逐个查询中断源，更慢

> [!TIP]
> 记法：向量表 = **按号直达的入口数组**，换速度、保「马上进 ISR」。

### 易混点

| 概念 | 要点 |
| --- | --- |
| 中断源 | 可来自外设、故障、陷阱、软件中断等 |
| 中断向量表 | **数组**存 ISR **入口地址**；按下标最快取入口，保障响应瞬时性 |
| 向量中断 | 由硬件/控制器给出服务程序入口（常经向量表） |
| 非向量 | 软件查询哪个设备 |
| 屏蔽/使能 | 用中断屏蔽字控制谁能打断 |
| 嵌套 | 高优先级可打断低优先级服务 |
| 中断隐指令 | 响应时硬件自动保存 **PC、PSW** 并**切入内核态**，不占程序指令；通用寄存器由 OS 保存 |
| 软中断 | 指令主动引发的内中断（相对外中断）；详见 [流水线与异常](../CPU/流水线与异常.md)、[操作系统概述](../../操作系统/概述.md) |

> 与 DMA 比：中断仍由 **CPU 执行传送指令**；DMA 传送阶段 **不经 CPU**。

## 5. DMA 方式

### 思想

- CPU 只做：**初始化**（设备地址、主存首址、长度、方向）与**结束处理**（计数完、校验、中断收尾）  
- 中间成批数据由 **DMA 控制器**在设备与主存间直接搬  

### 传送方式

| 方式 | 含义 |
| --- | --- |
| **停止 CPU 访存（成组/突发）** | DMA 占总线期间 CPU 暂停访存 |
| **周期挪用（周期窃取）** | DMA 插入占用若干存取周期，CPU 多数时间可算 |
| **交替访存** | CPU 与 DMA 分时用存储周期（实现成本较高） |

### DMA 与中断对比（高频）

| | 中断 | DMA |
| --- | --- | --- |
| 响应单位 | 多为字符/字级 | 数据块 |
| 传送执行者 | CPU | DMA 控制器 |
| 现场保护 | 要保护断点与大量寄存器 | 传送中一般不切进程；结束可中断 CPU |
| CPU 占用 | 相对高 | 相对低 |

### 简化流程

```text
CPU 置 DMA 参数并启动
  → 设备 ↔ 主存 成批传送（DMA 控总线）
  → 字节计数减到 0
  → DMA 向 CPU 发结束中断（收尾）
```

## 6. 通道方式

- **通道**：专用 I/O 处理部件，能执行**通道程序**（存放在**主存**，见 [总线](../总线/总线.md) 双总线叙述）  
- CPU：发启动；通道：选设备、控传送、汇集状态  
- 常见类型直觉：  
  - **选择通道**：一次选一台高速设备，适合磁盘等  
  - **字节多路通道**：交错服务多台低速设备  
  - **数组多路通道**：面向多台高速设备的成组传送（教材表述略有出入，以题面为准）  

相对 DMA：通道更能**并行管多设备**、程序化控制更强，大型系统常用。

- 状态位：忙 / 就绪 / 错误 / 中断允许
