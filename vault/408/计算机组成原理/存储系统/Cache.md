# Cache

> [!abstract] 一句话
> Cache 用 SRAM 贴近 CPU，靠局部性抬命中率；核心题型是 **\(t=\) 命中公式**、**映象方式**、**替换**与**写策略搭配**。

## Cache 性能

Cache 通常集成在 CPU 内，用 **SRAM**（集成度较低、速度快）。

设 \(t_c\) 为访问一次 Cache 时间，\(t_m\) 为访问一次主存时间，命中率 \(H\)：

\[
t = H t_c + (1-H)(t_c + t_m)
\]

（先查 Cache 未命中再访主存）

或在「Cache/主存并行启动」模型下：

\[
t = H t_c + (1-H) t_m
\]

看清题目假设再用哪个。

## Cache 和主存的映射方式

主存按**块**划分；Cache 与主存以块（页/页面/页框等叫法）交换。

### 全相联映射（随意放）

- 主存块可放入 Cache **任意**行；比较器多、灵活、硬件贵

### 直接映射

\[
\text{Cache 块号} = \text{主存块号} \bmod \text{Cache 总块数}
\]

### 组相联映射

\[
\text{组号} = \text{主存块号} \bmod \text{组数}
\]

![组相联](/vault/408/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BB%84%E6%88%90%E5%8E%9F%E7%90%86/%E5%AD%98%E5%82%A8%E7%B3%BB%E7%BB%9F/%E9%99%84%E4%BB%B6/Screenshot%202026-07-04%20at%2015-55-34.png)

- **n 路组相联**：一组内 n 块
- 注意模的是**组数**不是总块数

## Cache 替换算法

Cache 满了换谁？

| 算法 | 要点 |
| --- | --- |
| RAND | 随机 |
| FIFO | 先进先出；刚换出又用 → **抖动** |
| LRU | 最近最少使用；贴近局部性 |
| LFU | 按访问次数；短期热点未必未来还用，常不如 LRU |

## Cache 写策略

### 写命中

| 策略 | 行为 |
| --- | --- |
| **写回** | 只改 Cache；换出时若脏（脏位=1）才写主存 |
| **全写/写直达** | 同时写 Cache 与主存；常用写缓冲 |

### 写不命中

| 策略 | 行为 | 常搭配 |
| --- | --- | --- |
| **写分配** | 主存块入 Cache 再改 | 写回 |
| **非写分配** | 只写主存，不入 Cache | 全写 |
