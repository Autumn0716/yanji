# 进程管理

对应 **OS-2.1～OS-2.25**。[考纲拆分](../../../brain/research/408-syllabus/operating-systems.md)。

## 进程与线程（OS-2.1～2.4）

- **进程**：资源分配基本单位；PCB 描述；独立地址空间
- **线程**：调度基本单位；共享进程资源；切换开销更小
- **状态**：运行/就绪/阻塞（可扩展创建、终止、挂起）
- **实现**：内核级线程 / 用户级线程（线程库）；多对一、一对一、多对多
- **控制**：创建、撤销、阻塞、唤醒等原语

### 进程映像

PCB结构与程序和数据的结合

进程映像指的是一个*正在运行的进程*在操作系统内存中的完整布局和状态.

> 可以想象为进程的一个"完整快照"

### 进程与程序的区别

静态和动态特点

<Callout type="note" collapsible={false} defaultOpen title="动态性">
  动态性是进程最重要的特性,以此来区分文件形式的静态程序.
</Callout>

### 进程创建原语

申请空白PCB,为新进程申请一个唯一的数字标识符,为新进程分配资源,包括内存和IO

初始化PCB,插入就绪队列

PCB:
1. 进程标志信息
2. 进程控制信息
3. 进程资源信息
4. CPU现场信息
全局变量与PCB无关

### 进程的状态

进程通常有自己的生命周期,一般不需要用户显式撤销,通常随着进程运行的正常或者不支持结束而撤销

### 父子进程
父子进程之间共享物理地址,但是不共享虚拟地址

## 进程间通信 IPC（OS-2.5～2.8）

| 方式          | 要点                                                |
| ----------- | ------------------------------------------------- |
| 共享内存        | 最快；需同步                                            |
| 消息传递        | 直接/间接；send/receive                                |
| 管道          | 半双工常见；血缘进程匿名管道；命名管道                               |
| 信号（2025 新增） | 异步通知；常称「软中断式」（类比，非 CPU 软中断指令；见 [概述·软中断](./概述.md)） |

### 共享进程
全局变量是对同一进程而言的,
不同进程之间并不会共享全局变量
## CPU 调度与上下文（OS-2.9～2.14）

### 目标与实现

指标：CPU 利用率、吞吐量、周转时间、等待时间、响应时间。

调度时机；**抢占 / 非抢占**；idle（闲逛）进程；用户级 vs 内核级线程调度差异。

### 算法（应会清单）

FCFS、SJF/SPF（可抢占 SRT）、时间片轮转 RR、优先级、高响应比、**多级反馈队列**。

CPU繁忙性工作应该是**该类工作需要占用很长的CPU时间,而很少请求IO操作**

### 多处理机调度（2025 新增）

负载均衡、处理器亲和性等概念（深度 `uncertain`）。

### 上下文切换

保存/恢复寄存器与内核栈等；开销来源；区别于模式切换（用户↔内核）。

进程上下文包含:
进程现场信息,
进程控制信息
用户堆栈
进程状态
>不包含中断向量
### 线程切换
内核级线程中,同一进程中的线程切换需要用户态->核心态,系统开销比较大

> 在多线程条件下,每个线程拥有各自独立的栈

<Callout type="note" collapsible={false} defaultOpen>
  1. 线程切换时,需要保存当前线程的**栈基址寄存器**的值,并加载新线程的栈基址
  2. 同一个进程的线程共享进程的虚拟地址空间,因此不需要更新**页基址寄存器**的值
  3. 一个进程所打开的文件也是这个所有线程共享的,因此不需要更新**进程打开文件表**
</Callout>

## 死锁（OS-2.22～2.25）

**四必要条件**：互斥、占有且等待、不可抢占、循环等待。

| 策略    | 做法                 |     |
| ----- | ------------------ | --- |
| 预防    | 破坏四条件之一            |     资源有序分配策略|
| 避免    | 安全序列；**银行家算法**     |     |
| 检测+解除 | 资源分配图/检测算法；撤销或抢占资源 |     |

### 常见的解决方法
1. 终止一个死锁进程
2. 终止所有死锁进程
3. 从死锁进程处抢夺资源
也称为 **剥夺资源法** 以及 **撤销进程法**

矩形代表一个资源

### Tips

1. 死锁的预防方法可以确保系统中不再发生死锁
2. 银行家算法无法检测是否系统中发生了死锁,\*\*它只是判断系统中是否安全\*\* 并不确定是否死锁
