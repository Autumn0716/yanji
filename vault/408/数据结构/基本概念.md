## 数据结构（DS-1.1）

### 基本术语

| 术语 | 含义 |
| --- | --- |
| 数据 | 可输入计算机并被处理的符号集合 |
| 数据元素 | 数据的基本单位（可含若干数据项） |
| 数据项 | 不可分割的最小单位 |
| 数据对象 | 性质相同的数据元素集合 |

### 逻辑结构 vs 存储结构

- **逻辑结构**：元素间逻辑关系——集合、线性、树、图
- **存储结构（物理结构）**：逻辑结构在计算机中的表示——顺序、链式、索引、散列
- 运算定义在逻辑结构上，**实现**依赖存储结构

#### 一句话区别

| | 问什么 | 不关心什么 |
| --- | --- | --- |
| **逻辑结构** | 元素之间有什么关系？ | 内存里怎么摆 |
| **存储结构** | 这些关系在机器里怎么表示？ | 业务语义上的「谁是谁的孩子」本身 |

- 逻辑结构回答「**是什么关系**」：一对一（线性）、一对多（树）、多对多（图）、无关系（集合）。
- 存储结构回答「**怎么落地**」：连续地址（顺序）、指针/引用（链式）、索引表、散列槽。

同一逻辑结构可以对应多种存储；同一存储方式也可以承载不同逻辑结构。例如「线性表」是逻辑结构，顺序表与链表是两种存储；邻接矩阵与邻接表都在实现「图」这一逻辑结构。

#### 例子（线性表）

逻辑关系始终是：有唯一前驱/后继（首尾除外）。实现时：

- **顺序存储**：用连续数组表达「相邻」→ 随机访问快，插入删除常要搬移（见 [线性表](./线性表/线性表.md)）。
- **链式存储**：用指针表达「后继」→ 改局部指针即可插入删除，按位查找慢。

运算（如 `Insert`/`Delete`）先在逻辑上定义语义；时间复杂度、指针细节则取决于你选的存储。

#### 易错点

- 把「数组」当成逻辑结构——数组通常是顺序存储的实现手段；逻辑上它往往仍是线性表或特殊矩阵。
- 以为换存储就换了逻辑结构——链表仍是线性表，只是物理表示变了。
- 把 ADT 操作和某种具体存储绑死——ADT 强调「做什么」与「怎么存」分离。

### ADT

抽象数据类型 = 数据对象 + 数据关系 + 基本操作集合。强调「做什么」与「怎么存」分离。

## 算法（DS-1.2）

### 特性

有穷性、确定性、可行性、有输入、有输出。

### 评价

正确性、可读性、健壮性、效率（时间/空间）。

### 复杂度

- 时间：语句频度 → 渐进界（常用大 O）；区分最好/平均/最坏
- 空间：算法额外辅助空间
- 常见阶：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
